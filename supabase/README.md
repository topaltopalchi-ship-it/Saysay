# راه‌اندازی backend امن سای‌سای (مرحله اجرایی)

این پوشه زیرساخت سمت سرور را شروع می‌کند؛ به‌تنهایی به معنی فعال شدن ورود یا پرداخت در اپ نیست.

## چه چیزی اضافه شده است؟
- جدول پروفایل با نام کاربری یکتا؛
- جدول اشتراک‌ها و ثبت خریدهای فروشگاهی با هش توکن خرید؛
- سیاست‌های RLS برای محدود کردن مشاهده داده به صاحب حساب؛
- تابع Edge برای خواندن وضعیت اشتراک حساب احراز هویت‌شده. پاسخ فقط وقتی اشتراک را فعال می‌داند که تاریخ انقضا در آینده باشد.

## مراحل راه‌اندازی
1. یک پروژه Supabase بسازید و migration موجود در `supabase/migrations` را اجرا کنید.
2. در تنظیمات Authentication، سیاست رمز عبور و محدودیت تلاش ورود را تنظیم کنید.
3. Edge Function با نام `subscription-status` را deploy کنید و متغیرهای استاندارد Supabase را در محیط سرور نگه دارید. کلید service-role هرگز نباید داخل اپ، GitHub، یا فایل `.env` عمومی قرار بگیرد.
4. اپ هنوز باید به Supabase Auth متصل شود و توکن نشست را در هدر `Authorization: Bearer ...` برای تابع بفرستد. این اتصال در این commit انجام نشده است.
5. برای ورود واقعی با نام کاربری (نه ایمیل)، باید یک جریان سروری امن برای نگاشت نام کاربری به حساب Auth پیاده شود؛ نام کاربری نباید از سمت کلاینت به ایمیل قابل حدس تبدیل شود.
6. پرداخت کافه‌بازار تا زمان پیاده‌سازی و آزمون تأیید رسید با API رسمی بازار، فعال محسوب نمی‌شود. تابع وضعیت اشتراک به‌تنهایی خرید را تأیید نمی‌کند و کلاینت اجازه نوشتن رکورد اشتراک ندارد.

## مرز داده‌ها
اطلاعات فروش، مشتریان، موجودی، چک‌ها و حساب‌های مالی در IndexedDB دستگاه می‌مانند. این migration هیچ جدول یا endpoint برای بارگذاری آن اطلاعات ایجاد نمی‌کند. ورود روی گوشی جدید، به‌خودی‌خود اطلاعات مالی دستگاه قبلی را بازیابی نمی‌کند.
